# IT Ticketing Dashboard — Human-Centered Design & Evaluation

**IE 8020 · Design of Human–Computer Systems · Clemson University · Spring 2025**

A course team project exploring how an IT support dashboard could help staff identify urgent tickets, navigate work and support management oversight. The project followed four deliverables: identifying customer and user needs; defining target specifications; generating and selecting concepts; and detailed prototyping, testing and refinement.

## What I learned

I learned to connect user research to design decisions: scope a problem with a mission statement, investigate underlying needs, organize and prioritize those needs, define measurable specifications, compare alternative concepts, prototype interactions and interpret usability feedback. My involvement spanned interviews, needs analysis, specifications, concept sketches, Axure prototyping, usability testing, report writing and coordination, within the team's shared project.

## Project at a glance

| Element | Scope |
| --- | --- |
| Context | CECAS CORE IT support workflows at Clemson |
| Research | The presentation reports 10 interview participants across help desk staff, managers and directors |
| Synthesis | 8 primary and 18 secondary needs in the final report |
| Design | 8 concepts, screening and a combined concept |
| Deliverables | Axure prototype, final report, presentation and implementation plan |
| Evaluation | Stakeholder feedback, task timings, a 1–5 intuitiveness rating and a reported SUS score |

## Scope of the outcome

The delivered coursework demonstrates design research, a prototype and usability evaluation. Backend integration, staff training, monitoring and rollout appear in the implementation plan. Numbers displayed inside prototype dashboards are sample interface content. The mission statement's 40% satisfaction improvement was a goal; the materials do not establish a measured 40% improvement.

The submitted PDF is preserved as supplied. Its appendices contain personas, specifications, concept screening and final interface views. The original Axure file requires compatible Axure RP software; it is not a browser export. Screenshots in `evidence/` are extracted from the report. Interview recordings, private peer evaluations and personal class notes are not part of this public repository.
